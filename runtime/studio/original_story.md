# 原创故事与分镜的入口

本入口仅适用于短剧。先读取项目类型；广告项目应返回原版广告 brief 到正式脚本的专用流程，不创建分集原文。

这是小说改编流程之前的原创输入阶段。`episode_source_missing` 表示需要准备故事，不表示 Agent 不能创作。不要让要求你写故事的用户先自行写完原文，也不要推荐没有工具支撑的“直接创建空白正式剧本”。

## 先确定当前集的真实状态

用 `mcp__arcreel__get_project_content` 读取项目及分集，使用客户端本轮提供的正式集 ID。已有正式脚本用 `get_episode_script`，已有故事用 `get_source_text` 读取。客户端的空本地输入框不代表正式故事或脚本不存在。

区分四层：故事/成品剧本原文 → `generate_script_plan` 的分镜内容规划 → 内容确认后的正式脚本 → `generate_episode_script` 补写画面提示词。最后一个工具不能替代前两个阶段。已有故事要求拆分镜，应直接规划，不重新创作故事。

## 一句话原创

1. 用户已要求原创时，调用 `Agent` 的 `write-original-story` 子智能体，传当前集 ID、创作要求、风格/时长/角色约束。它自行读取同剧共享资产并写故事，不向主 Agent 搬运长篇原文。必要的创作细节可按用户意图合理补齐。
2. 写手通过 `mcp__arcreel__edit_source_text({"episode_id": N, "text": "完整故事正文"})` 登记到**当前已存在的集**。该工具明确支持无原文的集；不要使用 `upload_source(role=episode)` 另建一集，不用 Write/Edit/Bash 写受保护目录。
3. 如果用户只要故事，登记并读取核对后返回概要与本集原文入口，停止。不擅自拆镜或生成图片/视频。
4. 用户还要求拆镜、角色/场景图或后续制作时，故事登记后刷新 `get_workflow_plan`，继续原版的 `generate_script_plan({"episode_id": N, "instructions": "本轮分镜要求"})`。分镜规划按项目制作方式产出，必须等待工具终态，不把已提交当完成。
5. 读取规划并向用户展示分镜概要；内容确认依照原版要求，通过用户确认后再 `confirm_script_review`。如果用户本轮明确批准自动确认这次新规划，可直接按该授权继续。已有产物覆盖仍须按返回的影响清单和 revision 确认。
6. 正式脚本存在后，需要画面提示词才调用原版 `create-episode-script` 子智能体或 `generate_episode_script`；角色/场景图依用户授权生成，勿把“拆分镜”理解为要求生成付费分镜图片或视频。

## 失败与继续

工具未被发现时先用 ToolSearch 搜索上述确切名称，不把未发现当作不存在。发现已有故事或规划时从该阶段继续，禁止重复覆盖。只根据实际回执报告完成的阶段；失败说明具体阶段与原因。所有操作留在当前客户端与当前项目，无须打开旧网页。
