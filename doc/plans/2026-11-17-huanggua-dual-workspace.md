# 黄瓜 AI 双模式工作区与 ArcReel 本地执行

## 范围与状态

统一主窗口顶部导航，保留无限画布，新增客户端内的短剧工作区。两种模式保留各自状态；短剧使用独立的 UI 草稿，不接管画布项目，不运行 ArcReel Agent、不提交付费任务。没有旧项目迁移、外部网页或旧启动器接入。

已实现：短剧项目创建/选择、分集添加/选择、剧本与制作要求编辑、手动分镜及描述/时长编辑；自动保存到本机；人物/场景、视频、审查、成片界面与真实能力提示；公共资源库、账号、设置和当前画布 Agent 任务概览。未接入的生成、审查和导出操作明确禁用。任务概览当前仅显示已加载的画布 Agent 任务，不声称跨项目/跨引擎完整汇总。

## 入口与边界

- `components/studio/WorkspaceChrome.tsx`：共用导航、资源库入口、任务概览；复用账号和现有设置面板。
- `components/studio/StudioWorkspace.tsx`：分集导航、六阶段内容区、制作要求面板；复用 Tabs、Select、ModalOverlay 和 UI Kit。
- `store/store.studio.ts`：通过主 Store slice 管理短剧 UI 草稿与操作。编辑、分集与项目切换均经 Action。
- `services/studioDraftRepository.ts`：独立 `huanggua-studio-drafts` IndexedDB，版本 1、单工作区文档。与 ArcReel 正式项目数据库及画布存储分离；不含密钥或媒体字节。后续接后端需要显式定义草稿转正式项目合同。
- `types/studio.ts`：项目、分集、镜头与阶段类型。
- `styles/huanggua-workspace.css`：使用现有外观 token；窄窗口 Agent 面板转为可关闭侧面板。
- `App.tsx`：仅装配工作区、保留 Canvas 挂载、关闭/重启前等待草稿保存。
- `store.ui.ts`、`useKeyboardShortcuts.ts`、`Canvas.tsx`：模式切换与快捷键/粘贴隔离，短剧 Ctrl+S 保存自己的草稿，不写隐藏画布。

保存采用顺序队列和修订检查；失败保留内存编辑并显示重试状态，读取失败阻止覆盖存储。原生关闭和性能重启遇到草稿保存失败会中止关闭。当前仅主窗口编辑，未开放短剧独立窗口或并发多客户端编辑。

## 第二阶段：本地执行接入（当前）

本节取代上文 UI 阶段的“未接入执行”状态。仍仅本地修改，不提交、推送或部署。

- `src-tauri/src/studio_runtime.rs` 管理固定 Python 适配器和 Windows Job Object；主窗口 IPC 仅接受有限操作，不能传入可执行路径、命令行或请求地址。后台只监听随机回环端口，桌面端点使用原生持有的随机令牌，浏览器 Origin 被拒绝；ArcReel 内部 API 保持 JWT 鉴权，模型桥复核模型密钥。
- `runtime/studio/desktop_bridge.py` 复用 ArcReel Agent、正式项目 API、事件日志、生成队列和任务控制。根据客户端项目 ID + 分集 ID 派生稳定执行项目，每集独立会话，避免跨集写回。模型调用按用户明确填写的制作要求执行；开始制作会消耗真实账号额度。
- 模型授权通过固定黄瓜账号接口读取。API Key 仅放 Python 进程内存，数据库保存不可用的内存句柄；重启必须重新读取授权。桌面会话仍由原生 secret_store 提供，退出登录或账号复核失败会关闭执行进程。执行目录在原生私有凭据目录下，普通文件接口不可读。
- `store.studioExecution.ts`、`studioExecutionService.ts` 管理会话观察和请求身份。提交前保存请求 ID；网络结果不确定保留原请求，恢复使用同一幂等键，不自动重新生成。模式切换不停止观察，重新打开应用后读取后台绑定和真实日志；停止 Agent 与取消队列任务是两个不同操作。
- 产物从标准项目输出目录登记，原生下载验证 SHA-256、体积与目标路径，原子发布到现有个人资源库的全局文件目录；按内容摘要去重，修订后内容作为新版本保留。入库失败可单独重试，不调用生成模型。图片、视频、音频可在短剧工作区预览，文本/JSON/Markdown 也进入个人库。
- `StudioAgentPanel` 支持真实对话、模型选择、制作要求、停止、任务状态和用户问题回答；`StudioResults` 展示实际产物。舞台编辑器的手写草稿与 ArcReel 正式剧本仍分开，不将后台输出无条件覆盖用户正在编辑的内容。

开发依赖由 `scripts/prepare-studio-runtime.ps1` 准备独立的引擎源码快照，只复制应用代码、公开模型元数据和许可证；不复制旧账号、项目、数据库或启动器。运行依赖使用本地已有 Python/Git。当前原生命令仅 debug 构建开放；正式打包需要固定版本、摘要与安装流程，尚未实现发布版内核分发。

本轮已验证：应用类型、定向 ESLint、默认特性的 Rust `cargo check --lib`；9 项前端草稿/执行测试、2 项离线后端集成检查；真实账号配置成功。桌面实际 Agent 已启动并调用工作流工具，正式脚本目录的直接写入按 ArcReel 原规则拒绝。真实产物入库验收将在完成后补录。

验收：登录 → 短剧模式自动连接 → 编写明确制作要求并选择模型 → 开始制作 → 观察工具/会话与任务 → 查看生成资源及个人库 → 切换画布并继续使用同一资源。异常检查：断网恢复同一提交、停止 Agent、取消具体任务、磁盘写入失败后仅重试入库、退出登录关闭进程；发布安装包与完整成片流程不在本轮已验证范围。

回退仅撤销本轮组件、slice 和装配入口，保留独立草稿库和原有画布项目；不得直接删除本地用户草稿。

## 第三阶段：真实生成与自动入库验收

仍仅本地开发。真实账号通过 ArcReel Agent / MCP 生成一张“雨夜旧书店”场景图（PNG，1672 × 941）和一份文字梗概；生成队列确认场景任务成功，图片解码校验通过。

验收发现并修复：

- 客户端分集仅存在于 UI 草稿，正式执行项目没有对应分集。提交现在保存分集标题与原文快照，通过正式分集 API 初始化；已有正式分集不覆盖，结果不确定时恢复原始快照与同一请求 ID。
- 分镜模式的视频默认候选包含不支持首帧的模型。候选按账号返回的能力筛选为支持首帧的模型。
- 已登记文件修改后旧摘要地址仍可能交付新版内容。下载前复核内容摘要，变化时返回冲突；原生下载仍再次校验 SHA-256。
- Windows 恢复带子 Agent 历史的会话时，SDK 临时导出路径超过 MAX_PATH。新增仅作用于当前 SDK 恢复导出器的路径兼容层，同时覆盖 JSONL、元数据和临时目录清理；保持原有路径越界检查，不修改共享 Python 安装。
- 内存凭据尚未恢复时，启动生成队列可能过早接手旧任务。`account_worker.py` 将恢复执行延后到账号验证及模型配置完成；未登录不启动生成，重复账号检查不重复启动队列。实际重启后接续原视频任务，供应商任务 ID 与队列数量保持不变。
- 模型选择原为面板临时状态，现按分集保存并验证面板重开、客户端重新加载后保留；显示的有效候选与提交模型保持一致。重启后即使 Agent 会话停止，只要原生成任务仍在运行，界面明确显示后台任务并禁用再次制作；取消入口仅用于引擎支持的排队任务。

应用类型检查、定向 ESLint、4 项执行测试、2 项离线集成检查通过。额外 Windows 回归检查验证了超过 260 字符路径下的子 Agent 历史与元数据导出、目录清理以及越界路径拒绝。

后续定向检查通过：5 项草稿持久化测试（包含按集保存模型）、1 项账号授权前不恢复任务且授权后只启动一次的队列生命周期检查；两项离线适配器集成检查再次通过，默认特性的原生开发构建成功。

桌面实际验证：从空个人库进入短剧模式后，客户端自动发现并导入场景图片与文字文件，两项显示“已进入个人资源库”；公共文件目录中两项内容摘要与后端登记一致。个人库图片大图正常显示，文字预览显示 UTF-8 正文；重启并重连后仍为原来两项文件、一个正式分集，没有重复导入或新增分集。原有画布项目 `111` 正常打开。

Windows 长路径修复编译进入开发客户端，已核对嵌入适配器摘要与源码一致；使用“恢复上次提交”成功续接同一请求，原生接口返回成功，原会话继续执行。

从桌面制作要求实际提交：单镜头脚本规划 → 确认规划 → 正式剧本提示词 → 分镜图。对应任务均成功；正式脚本只有一镜、2 秒，复用既有场景，没有对白或新增人物。正式镜头 ID 以 ArcReel 确认后的 `E1S02` 为准。分镜图及剧本各内容版本自动进入个人库。视频仅提交一次，供应商已登记任务并返回 `in_progress`，视频产物、播放与最终重启检查仍待任务返回后补录，不标为已通过。

本地重启与重新加载后，个人库仍为 6 项（两张图片、文字梗概及三个正式脚本内容版本），没有重复文件。视频任务重启恢复查询成功，等待超过 40 分钟时上游仍返回 `in_progress`、进度 1，状态查询 HTTP 200；客户端保持观察原任务，不重新生成。视频成功返回、自动入库及播放仍是未完成验收项；尚未验证完整多镜头成片导出。
